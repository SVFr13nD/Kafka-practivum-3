# Настройка Kafka
## Kafka-кластер
Для задания я использовал Kafka из трёх брокеров.
У каждого брокера свой номер:
- Broker 1 — ID 1
- Broker 2 — ID 2
- Broker 3 — ID 3
Также используется ZooKeeper.
Всё запускается через Docker Compose.
## Kafka-топики
Я создал четыре топика:
| Топик | Для чего нужен |
|---|---|
| `messages` | Сюда приходят сообщения |
| `filtered_messages` | Сюда попадают проверенные сообщения |
| `blocked_users` | Для блокировки и разблокировки пользователей |
| `banned_words` | Для добавления и удаления запрещённых слов |
У каждого топика одинаковые настройки:
```text
Partitions = 1
Replication Factor = 2
```
Одна партиция нужна для простоты задания.
Replication Factor 2 означает, что данные хранятся в двух копиях на разных брокерах.
## Настройка репликации
В Kafka настроено:
```text
min.insync.replicas = 2
```
В Docker Compose:
```yaml
KAFKA_MIN_INSYNC_REPLICAS: 2
```
Это значит, что для записи с `acks=all` нужны две синхронизированные реплики.
Если одна из двух реплик недоступна, такая запись не пройдёт, пока не восстановится нужное количество реплик.
## Faust Tables
В программе используются две таблицы:
```text
blocked_users_table
banned_words_table
```
Первая хранит информацию о заблокированных пользователях.
Вторая хранит запрещённые слова.
Faust также создаёт специальные Kafka-топики:
```text
message-moderation-blocked-users-table-changelog
message-moderation-banned-words-table-changelog
```
Они нужны для восстановления данных таблиц после перезапуска программы.
Для них используется Replication Factor 2.
Также применяется настройка:
```text
cleanup.policy=compact
```
Она позволяет Kafka со временем удалять старые значения одного ключа, оставляя актуальное.
Например:
```text
spam = True
spam = False
spam = True
```
Последнее значение показывает, что слово `spam` сейчас запрещено.
## Подключение к Kafka
Для подключения используются адреса брокеров.
Если программа работает внутри Docker, используются внутренние адреса:
```text
kafka-broker-1:29092
kfka-broker-2:29092
kafka-broker-3:29092
```
Если подключаться с компьютера, используются:
```text
localhost:9092
localhost:9093
localhost:9094
```
Для локального запуска можно указать адреса через PowerShell:
```powershell
$env:KAFKA_BROKER="kafka://kafka1:9092;kafka2:9093;kafka3:9094"
```
Здесь нужно указать реальные адреса своих брокеров.
Для Docker используется:
```text
kafka://kafka-broker-1:29092;kafka-broker-2:29092;kafka-broker-3:29092
```
## Количество партиций
В настройках приложения указано:
```python
TOPIC_PARTITIONS = 1
BANNED_WORDS_PARTITIONS = 1
TOPIC_REPLICATION_FACTOR = 2
```
То есть у каждого основного топика одна партиция и две копии данных.
Для учебного задания этого достаточно.
## Проверка топиков
Чтобы посмотреть все топики, выполняю:
```bash
kafka-topics --bootstrap-server localhost:9092 --list
```
Чтобы посмотреть настройки конкретного топика:
```bash
kafka-topics --bootstrap-server localhost:9092 --describe --topic banned_words
```
Для проверки changelog:
```bash
kafka-topics --bootstrap-server localhost:9092 --describe --topic message-moderation-banned-words-table-changelog
```
Проверяю, чтобы было:
```text
PartitionCount: 1
ReplicationFactor: 2
```
Также смотрю `ISR`, чтобы обе реплики были синхронизированы.
## Kafka UI
Для удобства я использовал Kafka UI.
После запуска Docker интерфейс доступен через браузер на порту `8080`.
Через него можно посмотреть топики, сообщения, партиции, реплики и настройки Kafka.
Это удобнее, чем каждый раз выполнять команды в консоли.
## Как всё работает
Сообщения отправляются в `messages`.
Программа Faust получает их и проверяет блокировки пользователей.
Если пользователь заблокирован, сообщение не проходит.
Если блокировки нет, программа проверяет запрещённые слова.
После этого сообщение отправляется в `filtered_messages`.
Топики `blocked_users` и `banned_words` используются для изменения блокировок и списка запрещённых слов.
## Итог

Создал четыре основных топика, настроил одну партицию и две реплики.
Также настроил `min.insync.replicas=2` и подключил Faust.
Проверил топики через команды Kafka и Kafka UI.
