# Kafka и Faust
Для третьей практической работе
Что было сделано:
- проверять, заблокирован ли отправитель;
- искать запрещённые слова в сообщении;
- заменять запрещённые слова на `****`;
- отправлять нормальные сообщения в другой топик.
Если пользователь заблокирован, его сообщение дальше не отправляется.
## Какие топики используются
- `messages` — сюда приходят сообщения;
- `filtered_messages` — сюда попадают сообщения после проверки;
- `blocked_users` — информация о блокировках;
- `banned_words` — список запрещённых слов.

Для хранения блокировок и запрещённых слов используются Faust Tables. Состояние также записывается в Kafka changelog-топики, чтобы его можно было восстановить после перезапуска.
Kafka настроены 3 брокера, у топиков 1 партиция и replication factor 2.
## Как запустить
Сначала создаём виртуальное окружение: py -3.13 -m venv .venv
Включаем его: .\.venv\Scripts\Activate.ps1
Ставим библиотеки: pip install -r requirements.txt
Указываем адреса своей Kafka: $env:KAFKA_BROKER="kafka://kafka1:9092;kafka2:9093;kafka3:9094" --Это пример адресов, их надо заменить на свои.
Запускаем программу:python -m app.main worker -l info
Когда появится `Worker ready`, программа запустилась.
Проверка:python .\scripts\test_data.py
Скрипт сам отправит тестовые данные в Kafka.
Сделал такие случаи:
1. Добавил запрещённое слово `spam`.
2. Отправил сообщение `This is **** message`.
3. Пользователь `user_2` заблокировал `user_1`. Сообщение от `user_1` не прошло.
4. Сообщение от `user_3` прошло, потому что он не заблокирован.
5. Разблокировал `user_1`. Его сообщения снова проходят.
6. Удалил `spam` из запрещённых слов. После этого слово больше не заменяется.
По логам теста всё это отработало.


Если запускать через Docker Compose: docker compose up -d --build
Посмотреть контейнеры: docker compose ps
Посмотреть логи программы: docker compose logs -f faust
Остановить: docker compose down


Более подробные записи есть в папке `docs`.
